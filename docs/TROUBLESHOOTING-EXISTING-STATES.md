# Troubleshooting existing LaunchFlow states

This guide maps **existing** states to their likely operation stage; it does not claim that each message uniquely identifies a root cause. Use synthetic values and never attach real credentials, account names, selectors, login URLs, browser profiles or decrypted vault files.

| Visible message or symptom | Stage / where to inspect | Safe evidence and next action |
|---|---|---|
| **Unsaved changes**, **Save changes** | [MainWindow.Persistence.cs](../LaunchFlow/MainWindow.Persistence.cs) `MarkUnsavedChanges`: edit captured but not yet durably committed | Record whether editing, importing or locking was underway, the button label and timestamp; manually retry Save while unlocked |
| **All changes saved** | `SaveAll` + `ConfigurationSaveTransaction.Commit` returned `CommittedAndPublished` | Check intended website/workspace after reopening a **synthetic** vault if acceptance testing; this label is not proof that Windows startup registration succeeded |
| **An earlier edit revision was saved; newer changes remain unsaved.** | `CommittedButSuperseded`: durable prior candidate succeeded but a later edit invalidated UI ownership | Recheck current selection and save the newer revision; do not misreport prior commit as rolled back |
| **Configuration was committed but not published in the UI.** | `CommittedButPublicationFailed`: durable write occurred, UI publication failed | Preserve state; reopen a disposable vault to compare. Do not blindly replay an overwrite |
| **Cannot save LaunchFlow** / autosave warning | Candidate validation or vault storage rejection; see `SaveAll`/autosave and `SaveTransactionState` | Record stage, exact app version, whether vault locked and sanitized error **category**, not exception messages containing personal paths |
| **Saved · Startup setup failed** | Post-commit Windows startup registration; encrypted save is already durable | Check per-user startup registration separately; do not repeat password storage or claim save failed |
| **Sign-in needs attention** / manual sign-in/MFA | [AutomationEngine.Login.cs](../LaunchFlow/Services/AutomationEngine.Login.cs) `RunOneAsync`/login verification stage; selectors, policy, provider behavior or unsupported challenge may differ | Note stage (username, password, submit, success verification), selected *synthetic* workflow ID, browser type and whether a safe manual confirmation was available. Do not export current page HTML or live URLs |
| **No saved credential** / **Missing required saved sign-in details** | Before credential-bound fill, after workflow login mode/provider selection | Confirm correct workflow association and explicit Passwords save; test with fake values. A website-field save does not save credentials |
| **KeePassXC not configured** / provider unavailable | `EnsureKeePassPasswordForRun` and [CredentialVault.cs](../LaunchFlow/Services/CredentialVault.cs): configured provider database/entry or policy unavailable | Record provider type (local vault vs KeePassXC) and whether local authorization/policy permitted it; do not include entry paths or passwords |
| **Sign-in confirmation was unavailable** | [MainWindow.Execution.cs](../LaunchFlow/MainWindow.Execution.cs) manual confirmation window ownership/availability | Record cancel/lock/navigation overlap and whether the same page remained current; do not use stale approval |
| **Browser cleanup did not complete; profiles retained and automation blocked** | [MainWindow.VaultLocking.cs](../LaunchFlow/MainWindow.VaultLocking.cs): context/recorder/Teach drain before sealing | Preserve profile files, close browser normally, retry Lock vault. Do not force-delete or unseal while contexts may be running |
| **Could not seal browser profiles; source files retained** | `ProfileVaultService.SealAll` after cleanup barrier | Capture whether browser processes remained open and OS file access/lock status, without copying profile data |
| **LaunchFlow exit paused** / update paused | [MainWindow.Lifecycle.cs](../LaunchFlow/MainWindow.Lifecycle.cs): exit permit denied for dirty editor, pending modal or incomplete lock/cleanup | Save edits, finish/cancel dialogs, retry secure lock and then exit. An installer pause is not permission to terminate and discard files |
| **Vault recovery required** / **Security upgrade required** | [App.xaml.cs](../LaunchFlow/App.xaml.cs), [VaultDatabase.cs](../LaunchFlow/Services/VaultDatabase.cs): absent, legacy, strict, incomplete or unsupported storage classification | Do not reset; preserve existing encrypted database and SQLite WAL/SHM together using a coherent backup. Use disposable synthetic vaults for reproduction |

## Safe evidence checklist

Record the exact tested **source SHA**, installed app/installer hash when available, operating system, synthetic case ID, operation phase, UTC timestamp, expected versus observed result, and whether the test was run under native Windows, linked-source simulation or Linux. For diagnostics, [DiagnosticReportService.cs](../LaunchFlow/Services/DiagnosticReportService.cs) exports only fixed allowlisted categories and Event/Failure codes; [CrashLog.cs](../LaunchFlow/Services/CrashLog.cs) drops arbitrary messages and raw exceptions. Consequently an exported report may show **that** a stage failed without explaining **why**. Do not broaden the export, enable URL/selector dumps or add raw exception text in the documentation-only maintenance slice.

Any new stage/reason enum, correlation ID or diagnostic schema is a separately authorized behavior/API change with privacy and retention tests; none is introduced here.
